# Synthetic governance policy
These are fictional capstone examples, not Superhuman policies.

## Classification
Public data may be shared externally after publication approval. Internal data is for authenticated employees only. Restricted data requires explicit access approval from its designated data owner. A classification label does not by itself specify a retention duration; consult the dataset's approved retention policy.

## Ownership
Each dataset must have a designated owner recorded in the live asset catalog. The owner reviews access requests and classification changes. These documents do not contain current ownership assignments. Current ownership of an individual table must be looked up in the live catalog, which this prototype does not yet access.

## Lineage
Lineage describes upstream inputs and downstream consumers. Before deprecating a dataset, inspect the live lineage catalog and contact downstream owners. This document does not list current dependencies.

## DSAR procedure
In this fictional workflow, data subject requests are submitted to the Privacy team through the internal request portal. The Privacy team verifies identity and coordinates the approved workflow. Do not include personal records in chatbot messages. This bot provides guidance only and cannot execute a request.

## Deletion
An owner must review downstream dependencies before approving deletion. Protected datasets cannot be deleted through the bot. This Q&A prototype cannot delete or modify datasets.
